## 플랫폼 자체 테스트 — 1.1 사용자 로직 (`isc_post`)

연산 1.1은 `xf::codec::resizeTop`이 출력을 쓴 뒤, 출력 화소마다 사용자 함수 `isc_post(px)`를 호출해 다시 씁니다. 위 1.0 기록과는 커널 바이너리가 다릅니다.

| 항목 | 내용 |
|---|---|
| 확인일 | 2026-11-10 |
| 환경 | 위와 같음, 작업 브랜치 `feat/operation-user-logic` (커밋 전) |
| 입력 | 위 1.0과 같은 `product_512.bin` (= 연산 문서의 `train_512.bin`), 512×512 → 256×256 |
| 사용자 로직 | `return px <= 30 ? 0 : px >= 220 ? 255 : (px - 30) * 255 / 190;` (연산 문서 2.3) |
| C 시뮬레이션 (g++, HLS 헤더) | 커널 소스 그대로 컴파일. 시작 파일 = 1.0 커널 C 시뮬레이션과 바이트 일치. 규칙 = 1.0 결과에 같은 규칙을 적용한 값과 일치. 크기가 8의 배수가 아닌 경우(500×333 → 251×167)도 일치 |
| hw_emu | **통과** — 출력 = 1.0 커널 C 시뮬레이션 결과에 같은 규칙을 적용한 값 (65,536화소 바이트 일치). 빌드+실행 약 5분 |
| hw_emu (로직 파일 없음) | **통과** — 시작 파일(`return px;`)로 빌드한 출력 = 1.0 커널 C 시뮬레이션 결과 그대로. 로직이 없으면 원래 연산과 같은 결과 |
| hw (U50) | **통과** (2026-11-11, 저장소에서 `isc run train_resize --target hw`, 실행 ID `20261111T040103-de9cd5`) — 카드 출력 = 같은 입력의 hw_emu 기준 출력 (65,544바이트 일치, `validation: cross_target`). kernel 1.126 ms |
| 참고 | 검증용 별도 작업 공간에서 실행했으므로 저장소의 실행 기록(`isc records`)에는 남아 있지 않습니다 |
